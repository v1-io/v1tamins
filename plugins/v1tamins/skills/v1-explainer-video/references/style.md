# Visual recipe: illustrated everyday system

Prefer this recipe for queues, handoffs, policies, and processes whose behavior can be shown through one concrete example. Honor a requested style. Use a literal interface when interaction details are the lesson, or precise geometry when quantities and mathematical relationships are the lesson. A recipe guides composition; it does not require a renderer, external assets, or a particular speech provider.

## Appearance

- Start with warm off-white, charcoal outlines, and two or three restrained accent colors. A useful starting palette is paper `#FFF7E8`, ink `#393B3C`, blue `#3578AA`, ochre `#C19136`, and green `#4B7952`; adapt it for contrast and the subject.
- Draw simple, recognizable objects with a consistent outline weight. Prefer a document, parcel, doorway, or person over anonymous boxes when the object clarifies the action. Characters are optional.
- Use readable sans-serif labels and captions. A restrained serif heading can give the scene warmth. Keep a clear size hierarchy and test at the actual viewing size; small decorative labels add clutter.
- Give one action most of the frame. Leave generous empty space and a separate caption area. Use color consistently, supported by shape or labels rather than color alone.

## Motion and voice

Follow one recognizable object through the explanation. Keep its shape and color stable; introduce another object only when it has a distinct role. Move, join, block, split, or transform things to reveal the mechanism. Hold the result of each important action long enough to inspect it. Avoid decorative bouncing, endless movement, and simulated drawing hands.

Use warm, direct spoken language. Explain what the viewer is seeing and why it matters. Let the illustration carry the relationship rather than filling the screen with the narrated sentences. A friendly appearance does not require jokes or a childish voice.

## Example: proposed repair versus checked result

Show a report unable to cross a gap. A bridge is added as the proposed repair, but no success mark appears yet. Visibly return the same report to the starting point and repeat its journey. Only after it arrives does the scene say “This check passed.” Keep the qualification that other cases remain untested.

Establish that the gap illustrates failed delivery and the bridge illustrates a proposed software change. Do not imply that software literally works like a bridge or that all failures have the same cause. Mark hypothetical examples as such. A real unresolved case must remain unresolved on screen.

## Apply and check

Before full production, render a representative frame and a short motion beat using the chosen palette, type, objects, and caption position. Use these to check legibility, object continuity, and whether the metaphor makes the causal distinction clearer. This is a production check, not an extra user approval gate.

Reject a metaphor if it needs more explanation than the actual process. Avoid sprawling whiteboards, stock office characters, status-card dashboards, and decorative scenery that competes with the action. The goal is a concrete, approachable explanation, not an illustration of every sentence.
